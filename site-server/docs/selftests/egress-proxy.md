# آزمونِ خودکارِ پراکسیِ سرورِ پردازش (برای وصل‌شدن به `apps/compute/selftests/`)

این قابلیت **نوعِ کارِ تازه‌ای برای سرورِ پردازش ندارد** (فقط `abagram_jobs.py` نسخهٔ ۱٫۲ پراکسیِ صفحهٔ «پراکسی و VPN» را می‌خواند)،
پس ماژولِ آزمونِ خودکارِ جدا لازم نیست؛ شرطِ قبول را همین سند می‌گوید و در صورت نیاز می‌شود به `selftests/` اضافه کرد.

## هر وقت گره روشن شد

1. **سایت جوابِ گره را می‌دهد**: `GET /api/v1/egress/node/` با `Authorization: Node <token>` ← `200` و
   `{"services": {"instagram": {"routed": false}}, "ttl_s": 300}` (تا وقتی مالک برای اینستاگرام پراکسی نگذاشته).
   بی‌توکن یا با توکنِ غلط ← `401`.
2. **گره پراکسی را می‌گیرد** (فقط اگر مالک در صفحه «اینستاگرام» را روی یک پراکسیِ بیرونی گذاشته و گره پراکسیِ خودش ندارد):
   کارِ `ig.health` با payload `{"test_connection": true}` ← در گزارش `caps["abagram"]`:
   `proxy` (بدونِ نام‌کاربری/رمز) پر است و `proxy_source == "site"`؛ آزمایشِ اتصال `reach.ok == true`.
3. **مستقیم‌کردنِ مسیر در صفحه** ← حداکثر ۵ دقیقه بعد `proxy` خالی می‌شود و `proxy_source == ""`.
4. **پراکسیِ خودِ مالک** (`NM_ABAGRAM_PROXY`، `proxy.txt`، پراکسیِ ویندوز یا داخلِ آباگرام) هرگز عوض یا برداشته نمی‌شود:
   `proxy_source` یکی از `env | file | system | abagram` می‌ماند.

## آزمونِ خودکارِ سایت‌سو (همین الان اجرا می‌شود)

* `apps.egress.tests.NodeTests` — چه چیزی به گره داده می‌شود (فقط سرویسِ `node=True`، فقط پراکسیِ قابل‌استفاده از بیرون، SOCKS بی‌رمز به‌شکل
  `socks5://`)، و اینکه نقطهٔ پایانی فقط گره را جواب می‌دهد.
* `processing/tests/test_abagram_jobs.py` — `fetch_site_proxy`، «فقط وقتی گره پراکسیِ خودش ندارد»، دنبال‌کردنِ تغییر و برداشتن،
  ماندنِ نشانگر بعد از ری‌استارت، سایتِ ساکت/قدیمی که چیزی را عوض نمی‌کند.
