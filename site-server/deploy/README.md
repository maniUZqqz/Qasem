# دیپلوی آپ‌مارکت

```bash
cp .env.production.example .env
# مقادیر REQUIRED را پر کن
docker compose up -d --build
```

---

## چه چیزی بالا می‌آید

| سرویس | کار |
|---|---|
| `db` | PostgreSQL 16 |
| `redis` | صف Celery، با `appendonly` تا ری‌استارت صف را دور نریزد |
| `migrate` | یک‌بار اجرا می‌شود: migrate، collectstatic، seed_plans |
| `backend` | جنگو روی gunicorn |
| `worker-ai` | صف `ai` — تحلیل، کپشن، سناریو |
| `worker-gpu` | صف `gpu` — رندر تصویر و ویدیو، **یکی در هر لحظه** |
| `website` | سایت عمومی Next.js |
| `nginx` | یک مبدأ برای همه‌چیز |
| `backup` | دامپ شبانه، ۱۴ روز نگه‌داری |

**GPU در این استک نیست.** اولاما و کامفی روی ماشینی می‌مانند که کارت دارد و از
طریق `OLLAMA_BASE_URL` / `COMFYUI_BASE_URL` صدا زده می‌شوند — یا با
`AI_API_BASE_URL` کاملاً کنار گذاشته می‌شوند. به همین دلیل این استک روی یک VPS
ارزان هم بالا می‌آید.

## چرا دو ورکر جدا

رندر ویدیو ده‌ها دقیقه طول می‌کشد. اگر روی همان صف باشد، هر کپشن و هر تحلیلی
پشتش می‌ماند. صف `gpu` عمداً `concurrency=1` است چون یک کارت بیشتر نیست و دو
رندر هم‌زمان از همان دو رندر پشت سر هم کندترند.

## پیشرفت زنده (SSE) و محدودیتش

پنل برای دیدن پیشرفت کارها به `/api/v1/jobs/<id>/stream/` وصل می‌شود و به‌جای
پرسیدن هر ۲.۵ ثانیه، سرور خودش خبر می‌دهد. برای یک رندر ۴۰ دقیقه‌ای این تفاوت
حدود هزار درخواست است.

**ولی یک قید مهم دارد:** gunicorn اینجا با ۳ ورکر × ۴ نخ اجرا می‌شود — یعنی
۱۲ درخواست هم‌زمان برای کل محصول. هر اتصال باز، یک نخ را تا آخر عمرش اشغال
می‌کند. برای همین تعداد اتصال‌های زنده **در هر پروسه محدود** است
(`MAX_SSE_STREAMS`، پیش‌فرض ۴) و بیشتر از آن با `stream_unavailable` رد می‌شود؛
پنل خودش به حالت معمولی برمی‌گردد.

اگر تعداد مشتری‌ها زیاد شد، راه درست **عوض کردن نوع ورکر** است (gevent یا
uvicorn) که اتصال بی‌کار هیچ نخی نمی‌گیرد. این تغییر کل اپ را تحت تأثیر قرار
می‌دهد، پس تصمیمی است که باید آگاهانه گرفته شود — نه عارضه‌ی جانبی یک نوار
پیشرفت.

## چرا migrate سرویس جداست

اگر migrate داخل entrypoint باشد، هر replica هم‌زمان روی یک دیتابیس migrate
می‌زند. اینجا یک‌بار اجرا می‌شود و تمام.

## بکاپ

هر شب یک `pg_dump` فشرده در `./backups/` روی خودِ هاست — نه داخل ولوم، تا
بازیابی به زنده بودن کانتینر وابسته نباشد.

فایل اول با پسوند `.partial` نوشته و بعد از موفقیت rename می‌شود. فایل نیمه‌نوشته
با نام واقعی از نبودن بکاپ بدتر است، چون **شبیه** بکاپ است.

```bash
# بازیابی
gunzip -c backups/upmarket-2026-09-12_0300.sql.gz | \
  docker compose exec -T db psql -U upmarket -d upmarket
```

> بکاپی که دستی امتحان نکرده باشی، بکاپ نیست. یک‌بار روی یک دیتابیس خالی
> بازیابی‌اش کن.

## HTTPS

`nginx.conf` فقط روی ۸۰ گوش می‌دهد. برای TLS یا certbot جلویش بگذار یا ترمینیشن
را به پروکسی بالادست بسپار. بعدش در `.env`:

```
SECURE_SSL_REDIRECT=true
SESSION_COOKIE_SECURE=true
CSRF_COOKIE_SECURE=true
SECURE_HSTS_SECONDS=31536000
```

**قبل از داشتن گواهی این‌ها را روشن نکن** — ریدایرکت SSL بدون گواهی یعنی سایت
از دسترس خارج.

`CSRF_TRUSTED_ORIGINS` را هم پر کن؛ وگرنه لاگین ادمین پشت پروکسی ۴۰۳ می‌دهد و
شبیه رمز اشتباه به نظر می‌رسد.

## چیزهایی که settings در production سخت‌گیری می‌کند

- `DJANGO_SECRET_KEY` پیش‌فرض → بالا نمی‌آید
- `DJANGO_ALLOWED_HOSTS=*` → بالا نمی‌آید
- `EMAIL_HOST` خالی → بالا نمی‌آید (بازیابی رمز بی‌صدا از کار می‌افتاد)
- `MEDIA_STORAGE=s3` بدون کتابخانه یا بدون کلید → بالا نمی‌آید
- `DATABASE_URL` خالی → هشدار می‌دهد که روی SQLite است

## فایل‌ها: ولوم یا Object Storage

پیش‌فرض `MEDIA_STORAGE=local` است و برای **یک ماشین** درست است. با دو ماشین
غلط می‌شود: ولوم مشترک نیست، و ویدیویی که فروشگاه‌دار می‌خواهد همین الان منتشر
کند، دقیقاً روی یکی از آن‌هاست.

```env
MEDIA_STORAGE=s3
S3_BUCKET=upmarket-media
S3_ENDPOINT_URL=https://s3.ir-thr-at1.arvanstorage.ir
S3_ACCESS_KEY=...
S3_SECRET_KEY=...
```

پروتکل S3 است، پس آروان، لیارا و MinIO خودمیزبان هر سه کار می‌کنند.
`pip install -r requirements-production.txt` کتابخانه‌اش را می‌آورد.

> **اگر کلیدها را نگذاری، سرور بالا نمی‌آید.** رد شدن بی‌صدا یعنی فایل‌ها روی
> ولوم کانتینر نوشته می‌شوند و اولین دیپلوی بعدی همه‌ی ویدیوهای رندرشده را با
> خودش می‌برد — دقیقاً همان چیزی که این تنظیم برای جلوگیری از آن هست.

باکت **private** است و URLها امضاشده‌اند. باکتی پر از عکس محصول مشتری‌ها و
ویدیوی کمپین منتشرنشده، پوشه‌ی عمومی نیست.

## سلامت سرویس

| مسیر | چه می‌گوید | چه کسی می‌بیند |
|---|---|---|
| `/healthz` | زنده‌ام. هیچ چیزی را لمس نمی‌کند | باز — لودبالانسر رمز ندارد |
| `/readyz` | می‌توانم سرویس بدهم؟ دیتابیس و صف. ۵۰۳ اگر نه | باز |
| `/metrics` | عمق صف، نرخ شکست، کارهای گیرکرده، وضعیت موتورها | فقط staff |

`/readyz` را به orchestrator بده تا تا وقتی دیتابیس یا صف در دسترس نیست
ترافیک نفرستد. `/healthz` را برای restart خودکار.

`/metrics` عمداً در nginx باز نشده: عمق صف و نرخ شکست نقشه‌ی این است که چطور
ما را از پا دربیاورند، و ردیف‌ها اسم کار مشتری‌ها را دارند. اگر scraper
می‌خواهی، scraper را روی شبکه‌ی خصوصی بگذار.

> **کارِ منتظر تأیید، کارِ گیرکرده نیست.** `/metrics` این دو را جدا می‌شمارد،
> وگرنه یک قابلیتِ کاملاً درست هر روز شبیه قطعی به نظر می‌رسید.

## ⚠️ آنچه هنوز روی سرور واقعی امتحان نشده

این فایل‌ها روی سیستمی نوشته شده‌اند که **داکر ندارد**. چیزی که تأیید شده:

- YAML کامپوز معتبر است و وابستگی سرویس‌ها درست چیده شده
- تنظیمات جنگو با `DATABASE_URL` واقعی پارس می‌شود و PostgreSQL می‌سازد
- گاردهای production واقعاً جلوی بالا آمدن را می‌گیرند
- بیلد standalone سایت اجرا و روی پورت تست شد (۲۰۰ گرفت)

چیزی که **تأیید نشده**: ساخته شدن ایمیج‌ها و بالا آمدن استک. اولین
`docker compose up` باید روی سرور انجام شود و احتمال خطای کوچک هست.
