# موتورِ ساختِ ویدئوی تبلیغاتیِ سه‌بعدی با هوشِ مصنوعی — UpMarket 3D

> نسخهٔ مرتب‌شدهٔ ایده. متنِ اصلی (دو پاسخِ هم‌پوشانِ یک دستیارِ هوش مصنوعی) در `docs/idea.original.md` مانده است.

## ۱. ایده در یک بند

کاربرِ UpMarket می‌نویسد «برای این عطر یک تبلیغِ ۱۵ ثانیه‌ای بساز؛ یک خانم آن را از روی میز بردارد، نشان بدهد و دربارهٔ رایحه‌اش حرف بزند».
موتور به‌جای تولیدِ تک‌تکِ فریم‌ها با مدل‌های سنگینِ ویدئویی، یک **انسانِ سه‌بعدی**، **حرکت‌های آماده و قابلِ ترکیب**، **محیط و نورِ سه‌بعدی**، **صدا** و **کارگردانِ هوشِ مصنوعی** را کنارِ هم می‌گذارد و ویدئو را با موتورِ سه‌بعدی رندر می‌کند.
مزیت: کاراکتر، حرکت، محیط و دوربین یک بار ساخته می‌شوند و در هزاران تبلیغ دوباره به کار می‌روند؛ هزینه قابلِ اندازه‌گیری و کنترل است.

## ۲. اصل‌های طراحی

1. **هوشِ مصنوعی کارگردان است، نه انیماتور.** مدلِ زبانی فقط یک برنامهٔ محدود و قابلِ وارسی (JSON) می‌سازد: شات‌ها، حرکت‌ها از کتابخانه، دوربین، دیالوگ و زمان‌بندی. اجرای دقیق با موتورِ سه‌بعدی است.
2. **هیچ برنامه‌ای بی‌وارسی رندر نمی‌شود.** حرکتِ ناموجود، گذارِ نامعتبر، شاتِ بیرون از زمان، دیالوگِ بلندتر از شات و تعاملِ بی‌نقطهٔ تماس پیش از رندر رد می‌شود.
3. **هر لایه قابلِ تعویض است** (مقیاس‌پذیری): کاراکتر، منبعِ حرکت، محیط، محصول، دوربین، نور، صدا، موتورِ رندر و کارگرِ رندر هر کدام «فراهم‌کننده» (provider) با فایلِ معرفی (manifest) هستند. نسخهٔ بهتر = یک فراهم‌کنندهٔ تازه، نه بازنویسی.
4. **کیفیت با اندازه‌گیری، نه حدس.** هر رندر گزارشِ کیفیت دارد (فاصلهٔ دست تا نقطهٔ گرفتن، فریمِ سیاه، مدت، صدا…).
5. **اول پیش‌نمایش، بعد رندرِ نهایی.** رندرِ سنگین هیچ‌وقت داخلِ درخواستِ وب اجرا نمی‌شود؛ صفِ کار و کارگرِ جدا.
6. **صداقت دربارهٔ واقع‌گرایی.** خروجی «سه‌بعدیِ تمیز و سینمایی» است؛ رسیدن به «فیلمِ واقعی» به دارایی‌های ممتاز (کاراکترِ اسکن‌شده، مو و پوستِ باکیفیت) و GPU وابسته است و باید با آزمونِ کور سنجیده شود.
7. **سه راهِ ساخت، یک سند.** هوشِ مصنوعی، کد (SDK/CLI/API) و محیطِ گرافیکی (خطِ زمان) همه یک «سندِ صحنه» می‌سازند؛ هر چه یکی بسازد، دیگری ویرایش می‌کند.
8. **یک صحنه، چند خروجی.** همان صحنه ویدئو (MP4)، دارایی برای بازی و وب (GLB با انیمیشن)، و فایل برای نرم‌افزارهای سه‌بعدی (FBX/USD/BLEND) می‌دهد؛ کاراکترها و حرکت‌ها در هر جا دوباره به کار می‌روند.
9. **سخت‌افزارِ قوی‌تر = کیفیتِ بیشتر، بی‌تغییرِ کد.** کیفیت پروفایلِ داده‌ای است (نمونه، وضوح، زیرتقسیمِ پوست، تاریِ حرکت)؛ کارگرِ GPU خودکار پیدا و استفاده می‌شود.

## ۳. معماری

```
کاربر (پنلِ UpMarket 3D / API)
        │  درخواستِ متنی + محصول (نام، شکل، عکس)
        ▼
┌──────────────── وب (Django + DRF) ────────────────┐
│ پروژه‌ها · کتابخانهٔ دارایی‌ها · صفِ کار · تنظیماتِ AI │
│ کارگردانِ AI (LLM ⇐ JSON) + قالب‌ها + اعتبارسنج        │
└───────────────┬────────────────────────────────────┘
                │ کارِ رندر (HTTP، با توکن)
                ▼
┌──────────── کارگرِ رندر (روی سرور یا PC با GPU) ────────────┐
│ صدا (TTS) ⇐ منحنیِ دهان ⇐ Blender (صحنه، کاراکتر، حرکت، دوربین) │
│ ⇐ کنترلِ کیفیت ⇐ FFmpeg (صدا، زیرنویسِ فارسی، CTA) ⇐ MP4       │
└────────────────────────────────────────────────────────────┘
```

| لایه | نسخهٔ فعلی | ارتقای بعدی (بدونِ تغییرِ معماری) |
|---|---|---|
| موتورِ سه‌بعدی | Blender 4.5 LTS (بی‌مانیتور، با پایتون) | Unreal + MetaHuman به‌عنوانِ رندرکنندهٔ دوم |
| کاراکتر | MakeHuman/MPFB2 (CC0) — بدن، پوست، مو، لباس، اسکلتِ ۱۶۳ استخوانی با صورت و انگشت | کاراکترِ اسکن‌شده/ممتاز (FBX) با همان نقشهٔ استخوان |
| حرکت | کتابخانهٔ حرکتِ رویه‌ای (procedural) با IK و متادیتا | کلیپ‌های Mocap (Mixamo/CMU/ضبطِ اختصاصی) — اسکلت‌های mixamo و cmu آماده‌اند |
| تعامل با محصول | IK دست تا نقطهٔ گرفتن، خم‌شدنِ انگشت، چسباندنِ محصول به دست | پروفایل‌های گرفتنِ بیشتر، فیزیکِ تماس |
| محیط | استودیو، فروشگاه، خانه (رویه‌ای، مواد PBR) | محیط‌های اسکن‌شده، HDRI |
| صدا | TTS ِ سازگار با OpenAI (Metis، آزموده) + Piper (آفلاین، اختیاری) | صداهای اختصاصی |
| هماهنگیِ لب | ۱۵ ویسمِ استاندارد از روی حروفِ فارسی، چیده روی بخش‌های صدادارِ صدای واقعی + پلک، ابرو و سرِ هم‌زمان با تکیه‌ها | هم‌ترازیِ واجیِ دقیق (مدلِ گفتار) |
| کارگردان | LLM با کتابخانهٔ openai (تنظیم در جنگو ادمین) + بازخوردِ خطای وارس‌گر به مدل + ۵ قالبِ قاعده‌محور به‌عنوانِ پشتیبان | مدل‌های قوی‌تر، بازخوردِ کیفیتِ تصویر |
| رندر | پنج سطح: انیمیک، پیش‌نمایش، ۷۲۰p، ۱۰۸۰p، 4K (پروفایلِ JSON)؛ تشخیصِ خودکارِ GPU | مزرعهٔ رندر، EEVEE روی GPU |
| صف | صفِ کارِ دیتابیسی + کارگرِ HTTP | Redis/Celery، چند کارگرِ هم‌زمان |
| ذخیره | SQLite + فایل | PostgreSQL + فضای ابری |

### سخت‌افزارِ فعلی و پیامدش

سرور: ۲ هستهٔ CPU، ۳٫۸ گیگ رم، بدونِ GPU (اندازه‌گیری‌شده):

| سطح | تنظیم | زمانِ هر فریم روی سرور |
|---|---|---|
| انیمیک | Workbench، 360×640 | ~۰٫۷ ثانیه (۱۲ ثانیه ویدئو ≈ ۳ دقیقه) |
| پیش‌نمایش | Cycles، ۱۲ نمونه + حذفِ نویز، 360×640 | ~۱۳ ثانیه |
| نهایی | Cycles، ۴۸+ نمونه، 1080×1920 | چند دقیقه ⇐ **کارگرِ GPU لازم است** (RTX 3060: چند ثانیه) |

پس: پیش‌نمایش روی سرور (با اولویتِ پایین تا سایت‌های دیگر کند نشوند)، رندرِ نهایی با کارگرِ GPU که همان کد را روی کامپیوترِ دیگری اجرا می‌کند و کار را از سرور می‌گیرد.

## ۴. اجزا

### ۴.۱ کاراکتر
یک کاراکترِ اصلی با پوستِ دارای پراکندگیِ زیرسطحی، چشم، ابرو، مژه، دندان، مو و لباس. «دستورِ ساخت» هر کاراکتر یک فایلِ JSON است (جنسیت، سن، اندام، پوست، مو، لباس) ⇐ افزودنِ کاراکترِ تازه بدونِ کد.
معیارِ پذیرش: قابلِ قبول در نمای متوسط و نزدیک، دست‌ها و انگشت‌ها قابلِ کنترل، مجوزِ تجاری.

### ۴.۲ کتابخانهٔ حرکت و گرافِ حرکت
هر حرکت: شناسه، دسته، مدت (پیش‌فرض/کمینه/بیشینه)، وضعیتِ شروع و پایان، نیازها (مثلاً «محصول در دسترس»)، تماس‌ها (کدام دست، کدام نقطه)، و منبع (رویه‌ای یا کلیپ).
دسته‌ها: پایه (ایستادن، نفس، جابه‌جاییِ وزن)، دست (اشاره، توضیح، دست‌تکان‌دادن)، تعامل (دست‌دراز کردن، گرفتن، بلند کردن، نگه‌داشتن، چرخاندن، نشان‌دادن، گذاشتن)، سر و صورت (نگاه، پلک، لبخند، سر تکان دادن، حرف زدن)، تبلیغاتی (نگاه به محصول، نشان‌دادن به دوربین، دعوت به خرید).
گرافِ حرکت مشخص می‌کند از هر وضعیت به کدام وضعیت می‌شود رفت (مثلاً «نگه‌داشتنِ محصول» فقط بعد از «گرفتن»).
سه قابلیتِ پایه: **ترکیبِ نرم** (منحنی‌های نرم، هم‌پوشانی)، **IK** (رساندنِ دست به نقطهٔ دلخواه برای هر محصول بدونِ انیمیشنِ جدا)، **قیدِ تماس** (محصول بعد از گرفتن همراهِ دست، پاها روی زمین).
نسخهٔ اول باید سه تعامل را بی‌نقص انجام دهد: برداشتن از میز، نگه‌داشتن و نشان‌دادن، گذاشتن روی میز.

### ۴.۳ محصول
- حالتِ A: محصول در صحنه، بی‌تعامل (سریع، ارزان).
- حالتِ B: محصول در دست؛ مدلِ سه‌بعدی با ابعادِ واقعی، جنس و **نقطهٔ گرفتن**.
شکل‌های آماده: بطری، شیشهٔ عطر، جعبه، قوطی/تیوب، گوشی، ظرف. عکسِ محصولِ کاربر به‌عنوانِ برچسب روی بدنه می‌نشیند. بعداً: مدلِ GLB/FBX ِ فروشنده یا Image-to-3D.
قاعده: دست باید واقعاً بگیرد؛ محصول نباید فقط به کفِ دست بچسبد.

### ۴.۴ محیط، نور، دوربین
محیط‌ها: استودیوی تبلیغاتی، فروشگاه، خانهٔ مدرن (و بعداً دفتر کار). واقعی‌نمایی: نورِ سه‌نقطه‌ای، سایهٔ تماس، مقیاسِ درست، مواد PBR، عمقِ میدان، جزئیاتِ محیطی.
دوربین‌ها به چند الگوی معتبر محدودند: نمای متوسط، نمای نزدیکِ محصول، دالیِ آرام، از روی شانه، نمای قهرمانِ محصول. AI فقط از میانِ این‌ها انتخاب می‌کند.

### ۴.۵ صدا و هماهنگیِ لب
متن ⇐ تقسیم به جمله ⇐ TTS ⇐ زمان‌بندی ⇐ حرکتِ فک و لب ⇐ پلک، نگاه و حرکتِ سر ⇐ میکسِ گفتار و موسیقی. یک صدای فارسیِ باکیفیت در نسخهٔ اول.

### ۴.۶ کارگردانِ هوشِ مصنوعی
درخواست ⇐ انتخابِ قالب، محیط و کاراکتر ⇐ تقسیم به شات ⇐ انتخابِ حرکت‌ها ⇐ دیالوگ و زمان ⇐ دوربین ⇐ وارسیِ امکان‌پذیری ⇐ رندر.
قراردادِ برنامه (خلاصه):
```json
{"schema_version": "1.0",
 "project": {"duration_seconds": 12, "fps": 24, "aspect_ratio": "9:16"},
 "character": {"asset_id": "presenter_female_01"},
 "environment": {"asset_id": "studio_warm"},
 "product": {"asset_id": "perfume_bottle", "name": "…", "label_image": "…"},
 "shots": [{"id": "s1", "start": 0, "end": 3, "camera": "medium",
            "actions": [{"motion": "idle_breathing", "start": 0, "end": 3}],
            "dialogue": "…"}]}
```
اگر LLM در دسترس نباشد، قالب‌های قاعده‌محور همان برنامه را می‌سازند.

## ۵. خطِ تولید و وضعیت‌ها

`PENDING ⇐ PLANNING ⇐ PLANNED ⇐ SCENE_BUILDING ⇐ RENDERING ⇐ QUALITY_CHECK ⇐ ASSEMBLING ⇐ COMPLETED` (یا `FAILED` با پیامِ قابلِ فهم و امکانِ تکرار).
مراحل: انیمیک/پیش‌نمایش ⇐ کنترلِ کیفیت ⇐ رندرِ نهایی ⇐ مونتاژ (صدا، موسیقی، زیرنویس، CTA) ⇐ MP4.
کنترلِ هزینه: استفادهٔ دوباره از دارایی‌ها، پیش‌نمایشِ اجباری، حداکثر یک رندرِ هم‌زمان روی هر کارگر، زمانِ مجاز و امکانِ لغو.

### API
| مسیر | کار |
|---|---|
| `POST /api/video-projects/` | ساختِ پروژه |
| `GET /api/video-projects/{id}/` | وضعیت و خطاها |
| `POST /api/video-projects/{id}/plan/` | ساختِ برنامه (AI یا قالب) |
| `POST /api/video-projects/{id}/preview/` | انیمیک/پیش‌نمایش |
| `POST /api/video-projects/{id}/render/` | رندرِ نهایی |
| `GET /api/video-projects/{id}/result/` | لینکِ خروجی |
| `GET /api/assets/` | دارایی‌های مجاز |
| `/api/worker/…` | پروتکلِ کارگر: گرفتنِ کار، گزارشِ پیشرفت، فرستادنِ خروجی |

## ۶. کیفیت

- ظاهر: پوست، چشم، مو، لباس، سایه.
- حرکت: بی‌لغزشِ پا، بی‌پرشِ ناگهانی، سرعتِ طبیعی، انتقالِ وزن.
- تعامل: تماسِ درستِ انگشت با محصول، ماندنِ محصول در دست، سایهٔ تماس.
- تصویر: نور، لنز، حرکتِ دوربین، ترکیب‌بندی، عمقِ میدان.

آزمون‌های خودکار: فاصلهٔ دست تا نقطهٔ گرفتن، ماندنِ محصول در دست، پرش بینِ حرکت‌ها، فریمِ سیاه، فایلِ ناقص، مدت/ابعاد/FPS/صدا.
طبیعی‌بودنِ چهره و احساس همچنان بازبینیِ انسانی می‌خواهد.
