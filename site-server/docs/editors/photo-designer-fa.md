# طراحِ خودکار (نیمه‌خودکارِ ادیتور عکس) — راهنمای فنی

کد: `backend/apps/photoedit/designer/` — صفحه: پنل ⇐ ادیتور عکس ⇐ «نیمه‌خودکار» ⇐ «طراحِ خودکار».

## خط لوله

```
دستور + عکس
  1. analyze.py   تحلیلِ قطعی: روشنایی، پالتِ محصول (k-means)، زمینهٔ ساده یا شلوغ، جای سوژه (آلفا / فاصله از رنگِ زمینه / سالینسیِ طیفی)، امتیازِ «آرامیِ» هر جا برای متن
  2. ai.py        (اختیاری) برنامه‌ریز: الگو، متن‌ها، حال‌وهوا، اصلاحِ رنگ، حداکثر ۶ مرحلهٔ اضافه از کاتالوگ. مختصات نمی‌دهد.
  3. recipes.py   الگو ⇒ برنامهٔ کامل (۸ الگو × ۳ سبک). متن‌های خالی از دستور (تخفیف، قیمت، «…») یا پیش‌فرض پر می‌شود.
  4. toolspec.py  وارسیِ سخت‌گیرانهٔ برنامه (ابزار/کلید ناشناخته دور، مقدار در بازه، ترتیبِ فاز)
  5. build.py     برنامه ⇒ «حالتِ ادیتور» (همان JSON ِ پروژهٔ ادیتورِ دستی): لایه‌ها و تنظیم‌ها. محصولِ جداشده = عکسِ کتابخانهٔ PNG شفاف (matte.py)
  6. qa.py        رندرِ واقعی ⇒ کنتراستِ WCAG (بدترین ۱۰٪ پیکسل‌ها)، حاشیهٔ امن، سرریز، هم‌پوشانی، سلسله‌مراتب، تعادل ⇒ اصلاحِ خودکار
  7. ai.py        (اختیاری) منتقد: عکسِ رندرشده را می‌بیند و با معیارهای طراحی نمره/اصلاح می‌دهد؛ اصلاح‌ها با «زبانِ وصله» (set/remove/grade/mood) اعمال می‌شود؛ اصلاحی که امتیازِ قطعی را بیش از ۳ بدتر کند رد می‌شود
  8. engine.py    ۲ تا ۳ پیشنهاد؛ نتیجه در PhotoDesign؛ «اعمال» ⇒ PhotoProject + PhotoEdit (همان خط‌لولهٔ «ساخت»)
```

کفِ کیفیت: حتی اگر مدل هیچ نکند (یا مدلِ ضعیف باشد) خروجی با الگوها و قاعده‌ها کامل است. مدل فقط «انتخاب و نوشتن» می‌کند.

## بدون هوشِ مصنوعی

`design.ai.planner` و `design.ai.critic` می‌گویند کدام بخش اجرا شد و اگر نشد چرا (جملهٔ فارسی از `smart._why`: «اعتبار متیس تمام شده (۴۰۲)»، «سرورِ پردازش خاموش است»…). پنل همین را بالای نتیجه می‌نویسد. هیچ‌وقت خطای هوش مصنوعی طراحی را نمی‌کشد.

## API

| متد | مسیر | کار |
|---|---|---|
| GET | `stores/<id>/photo-editor/designer/` | الگوها، قاب‌ها، حال‌وهواها، کاتالوگِ ابزارها، فونت‌ها، وضعیتِ مسیرِ هوش مصنوعی |
| POST | `…/designer/analyze/` | `{asset, prompt?}` ⇒ تحلیلِ فوری |
| POST | `…/designer/designs/` | `{asset, prompt?, recipe?, format?, mood?, quality?, copy?, variants?, use_ai?}` ⇒ ۲۰۱، کار در Celery |
| GET / DELETE | `…/designer/designs/<pk>/` | وضعیت و پیشنهادها / حذف |
| POST | `…/designer/designs/<pk>/rerender/` | `{variant, plan}` ساختِ دوبارهٔ یک پیشنهاد با مرحله‌های ویرایش‌شده (بدونِ هوش مصنوعی) |
| POST | `…/designer/designs/<pk>/apply/` | `{variant}` ⇒ `{project, edit}` |

## آزمون

`backend/apps/photoedit/tests_designer.py` — رنگ و WCAG، تایپوگرافی و جاگیری، فونت‌ها، شبکه، وارسیِ برنامه، تحلیل و matte، همهٔ الگوها ×۳ سبک (بی نقصِ کنتراست/حاشیه/هم‌پوشانی)، اصلاحِ خودکار، حلقهٔ نقدِ هوش مصنوعی با مدلِ ساختگی (بدونِ هیچ تماسِ واقعی)، API، دورِ کاملِ «طراحی ⇒ اعمال ⇒ پروژه ⇒ نسخهٔ ساخته‌شده».

## افزودنِ الگوی تازه

۱) تابعی در `recipes.py` که `brief` را بگیرد و `{recipe, format, mood, variation, title, steps}` بدهد؛ ۲) یک ردیف به `RECIPES`؛ ۳) اگر ابزارِ تازه می‌خواهد: ردیفی در `toolspec.TOOLS`، `PHASE`، و `build.HANDLERS`؛ ۴) آزمونِ «همهٔ الگوها» خودکار آن را هم می‌سنجد.

## کاتالوگِ ابزارهای طراحِ خودکار
