# معماریِ UpMarket 3D (برای توسعه‌دهنده)

## جریانِ داده
```
خلاصهٔ کار (brief) ──► کارگردانِ AI / قالب / SDK / ویرایشگر ──► سندِ صحنه (up3d.scene/1)
                                                             │  validate + repair (گرافِ حرکت)
                                                             ▼
             برچسبِ محصول (Pillow) · صدا (TTS) · ویسم‌ها روی صدای واقعی (lipsync)
                                                             ▼
                                         compiled.json (up3d.compiled/1) — همه‌چیز به فریم
                                                             ▼  (بسته: compiled + inputs/)
                   کارگر ──► Blender: build ▸ animate ▸ realize ▸ face ▸ bake ▸ cameras ▸ gaze ▸ render/export
                                                             ▼
                         render.mp4 + engine_report.json (اندازه‌گیریِ واقعیِ کیفیت)
                                                             ▼
                 پنل: کنترلِ کیفیت ▸ نوشته‌ها و زیرنویسِ فارسی ▸ صدا/موسیقی ▸ FFmpeg ▸ final.mp4 ▸ کنترلِ فایل
```

## قراردادها
| قرارداد | فایل | چه کسی می‌سازد | چه کسی می‌خواند |
|---|---|---|---|
| manifest ِ دارایی | `assets/<kind>/<id>/manifest.json` | انسان/بستهٔ دارایی | همه |
| سندِ صحنه | `up3d/scene.py` | AI، SDK، ویرایشگر، API | وارس‌گر، compiler |
| برنامهٔ اجرایی | `up3d/compiler.py` | compiler | موتور (Blender امروز؛ هر موتورِ دیگر فردا) |
| نقشهٔ اسکلت | `engine/rigs/*.json` | انسان | ریگِ کنترلی، چهره |
| پروتکلِ کارگر | `up3d/worker.py` ⇄ `web/studio/api.py` | پنل | کارگرها |
| گزارشِ موتور | `engine_report.json` | `engine/up3d_engine/bake.py`, `render.py` | `up3d/qc.py` |

## موتور (engine/up3d_engine)
- `characters.py` فراهم‌کننده‌ها: `mpfb` (دستورِ ساخت) و `file` (هر کاراکترِ اسکلت‌دار + نقشهٔ نقش).
- `rig.py` ریگِ کنترلی روی هر اسکلت: هدفِ IK ِ مچ و پا (پاها کاشته)، قطبِ آرنج/زانو با **کالیبراسیونِ خودکار**،
  خمِ انگشت با پیدا کردنِ خودکارِ محور، نگاهِ سر/چشم (Damped Track)، کانال‌های نرم (Hermite ِ مهارشده، کواترنیون در فضای لگاریتمی)،
  لایه‌های افزودنی (نفس، جابه‌جاییِ وزن، لرزشِ ریز)، **محدودکنندهٔ سرعتِ مچ و دست**.
- `motions.py` کتابخانهٔ حرکت؛ هر حرکت از «وضعیتِ فعلی» شروع می‌کند و فقط کلیدِ معنایی می‌گذارد.
- `products.py` ساختِ محصول + نقطهٔ گرفتن؛ هنگامِ نگه‌داشتن، محصول با «تبدیلِ ثابتِ لحظهٔ گرفتن» همراهِ مچ است.
- `bake.py` یک دور روی همهٔ فریم‌ها: محصول به دست، مسیرِ سر/سینه برای دوربین و نگاه، و اندازه‌گیری‌ها.
- `face.py` ویسم‌ها (هم‌پوشانیِ مثلثی)، حالت‌های چهره، پلکِ تصادفیِ تکرارپذیر، ابرو و سرِ هم‌زمان با تکیهٔ گفتار.
- `camera.py` قاب‌بندی از روی ارتفاعِ قاب/لنگر/لنز، حرکت‌های دوربین، دنبال‌کردنِ نرمِ سوژه، برش با نشانگر.
- `render.py` پروفایل ⇐ تنظیمِ موتور، تشخیصِ GPU (OptiX⇐CUDA⇐HIP⇐oneAPI⇐Metal)، ادامهٔ رندرِ نیمه‌کاره.
- `export.py` پختنِ قیدها و خروجیِ GLB/FBX/USD/BLEND.

## نقطه‌های توسعه
1. کاراکترِ ممتاز ⇐ `provider: file` + `engine/rigs/<name>.json`
2. حرکتِ Mocap ⇐ `source: {type: clip}` و پیاده‌سازیِ `engine/up3d_engine/clips.py` روی همان نقش‌ها
3. محیطِ اسکن‌شده ⇐ `builder: blend_file`
4. بافت/HDRI ِ واقعی ⇐ `assets/textures/<id>` و `assets/hdri/`
5. موتورِ رندرِ دیگر ⇐ خواندنِ `compiled.json`
6. TTS ِ دیگر ⇐ تابعِ تازه در `up3d/tts.py` + manifest ِ صدا
7. صفِ توزیع‌شده ⇐ چند کارگر هم‌زمان کار می‌گیرند (قفلِ ردیف در `claim`)؛ PostgreSQL به‌جای SQLite با تغییرِ `DATABASES`

## آزمون‌ها
- `tests/test_core.py` هسته (دفتر، قالب‌ها، وارسی و ترمیم، compiler، لب، SDK، نوشتهٔ فارسی)
- `tests/e2e_api.py` سرتاسری از راهِ API (AI ⇐ ویرایش ⇐ رندر روی کارگر ⇐ مونتاژ ⇐ کنترلِ کیفیت)
- `tests/ui_smoke.py` مرورگرِ واقعی (Chromium): همهٔ صفحه‌ها، کشیدن در خطِ زمان، ذخیره، خطاهای جاوااسکریپت
