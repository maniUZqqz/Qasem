# UpMarket — چطور بدون مدل‌ها، کل پروژه را تست کنیم

سیستم توسعه نه مدل‌های Ollama را دارد نه مدل‌های ComfyUI را. برای همین سه لایه
تست وجود دارد که **کد واقعی** را اجرا می‌کنند و فقط خودِ مدل‌ها را با یک
شبیه‌ساز عوض می‌کنند.

## معمولاً کاری لازم نیست — `start.bat` خودش انجام می‌دهد

مرحلهٔ **۹/۹ Self-check** در `start.bat` قبل از بالا آوردن سرویس‌ها این دو را
اجرا می‌کند (حدود یک دقیقه، بدون GPU):

```
python manage.py selftest --quick     -> [OK] AI pipelines
python tools/e2e_api_test.py --queue  -> [OK] API end-to-end
```

اگر Redis پرتابل در پوشهٔ `redis\` نباشد، خودکار به حالت همگام برمی‌گردد
(بدون تست ویدیو). شکست که بخورد، آخرین خطوط لاگ را چاپ می‌کند و می‌پرسد ادامه
بدهد یا نه. رد کردن این مرحله: `start.bat /notest`.

## دستی — وقتی می‌خواهی عمیق‌تر بگردی

```bash
cd backend
python manage.py test                  # کل تست‌های واحد و یکپارچگی
python manage.py selftest              # سوییپ کامل: هر پایپ‌لاین × هر ۹ نوع خرابی مدل
python tools/e2e_api_test.py           # کل API روی HTTP — حالت همگام (بدون Redis)
python tools/e2e_api_test.py --queue   # همان، با Redis واقعی + دو Celery worker
python tools/e2e_api_test.py --only chat,payment_flow --keep   # فقط چند مرحله + نگه‌داشتن لاگ
cd ../frontend && npm run build        # type-check کامل فرانت
```

`selftest` بدون `--quick` هر المان را با **هر ۹ نوع خرابی** می‌سنجد (نه فقط
خروجی تمیز)؛ همان چیزی است که `start.bat` برای صرفه‌جویی در زمان کوتاهش می‌کند.

## سه لایه چه چیزی را ثابت می‌کنند

| لایه | چه چیزی واقعی است | چه چیزی جعلی است |
|---|---|---|
| `manage.py test` | مدل‌ها، سریالایزرها، دسترسی‌ها، staleness، ترمیم JSON، ffmpeg، ریسرچ | Ollama و ComfyUI (mock) |
| `manage.py selftest` | تسک‌های واقعی Celery، پرامپت‌ها، اعتبارسنجی‌ها، رکوردهای DB، درج متن با Pillow، اتصال ویدیو با ffmpeg | فقط پاسخ مدل و رندر |
| `tools/e2e_api_test.py` | سرور زندهٔ Django، JWT، همهٔ اندپوینت‌ها، Redis و Celery واقعی، فایل‌های مدیا روی HTTP، وبهوک n8n | فقط پاسخ مدل و رندر |

### شبیه‌ساز عمداً بد رفتار می‌کند

`backend/tools/fake_ai_stack.py` هر ۹ نوع خرابیِ واقعیِ مدل‌های محلی را بازتولید
می‌کند: نشت `<think>`، بلوک ```json، حرف اضافه قبل/بعد JSON، کامای اضافه، **کامای
جاافتاده** (دقیقاً خطای لاگ خود کاربر)، خروجی قطع‌شده، `response` خالی با JSON
داخل `thinking` (ایراد Qwen3-VL)، خطای ۵۰۰ کمبود VRAM، و مدلی که JSON معتبر ولی
**ناقص** برمی‌گرداند. ComfyUI هم مو‌به‌مو مثل واقعی جواب می‌دهد: `/upload/image`،
`/prompt`، `/history` که چند بار خالی است، `/view` که PNG و MP4 **واقعی**
برمی‌گرداند تا ffmpeg واقعاً فریم آخر را بکشد و قطعات را بچسباند.

## ۲۵ مرحلهٔ تست سرتاسری API

`tools/e2e_api_test.py` دقیقاً کاری را می‌کند که مرورگر می‌کند — لاگین با JWT و
بعد پیمودن همهٔ صفحه‌ها:

احراز هویت · فروشگاه و پروفایل برند · کاتالوگ (عکس/ویژگی/واریانت + رد فایل جعلی) ·
**ایزوله‌سازی بین کاربران** · هوش محصول · تحلیل بازار · استودیوی تصویر (۳ حالت) ·
کپشن‌ها · سناریوی ویدیو · تولید ویدیو · صداگذاری · چت فروش · پرداخت و رسید ·
تیکت و ارجاع به انسان · اعلان‌ها · کمپین‌ها · انتشار n8n · آمار · Jobها ·
جستجوی معنایی · مستندات API · محصول بدون عکس · حذف محصول ·
**خاموش‌بودن ComfyUI** · **خاموش‌بودن همهٔ سرویس‌ها**

چیزهایی که فقط اینجا ثابت می‌شوند و تست واحد نمی‌گیردشان:

- **هیچ Job سرگردانی نمی‌ماند** — بعد از هر سناریو، `GET /jobs/?active=true` صفر است.
- **شکست سریع و فارسی** — با همهٔ سرویس‌ها خاموش، چهار عملیات + چت در چند ثانیه
  با پیام فارسی شکست می‌خورند و اعلان `AI_ERROR` برای فروشنده ثبت می‌شود.
- **کلیک دوم روی «تولید ویدیو» ۴۰۹ می‌گیرد** و اجرای مجدد، قطعات `DONE` را
  **دوباره نمی‌سازد** (قانون ۸ مهندسی).
- **URLهای مدیا واقعاً باز می‌شوند** — پوستر و ویدیوی نهایی با HTTP دانلود
  می‌شوند، و URLی که به n8n می‌رود مطلق است و resolve می‌شود.
- **انتشار تکراری بلاک می‌شود** و `resend: true` صریح کار می‌کند.
- **حذف محصول** محتوای خودش را می‌برد و بقیهٔ فروشگاه را دست‌نخورده می‌گذارد.

## چیزهایی که این تست‌ها هرگز ثابت نمی‌کنند

فقط و فقط با سخت‌افزار و مدل‌های واقعی معلوم می‌شوند:

1. **کیفیت خروجی مدل‌ها** — آیا QwQ تحلیل فروشنده‌پسند می‌نویسد؟ آیا FLUX و
   Wan 2.2 روی RTX 3060 خروجی قابل‌فروش می‌دهند؟ این همان **فاز ۰.۵** رودمپ است
   که هنوز انجام نشده.
2. **زمان واقعی هر مرحله** — شبیه‌ساز در میلی‌ثانیه جواب می‌دهد؛ مدل ۳۲B و رندر
   Wan دقیقه‌ها طول می‌کشند.
3. **فشار VRAM** — هماهنگ‌کنندهٔ `services/gpu.py` تست شده که *فراخوانی* می‌شود،
   ولی اینکه ۱۲ گیگابایت واقعاً کفایت کند اینجا معلوم نمی‌شود.
4. **پیوستگی تصویری ویدیو** بعد از چند قطعه.
