# API و وب‌هوکِ صندوق پیام

این راهنما برای کسی است که می‌خواهد سیستم خودش (سایت فروشگاه، CRM، اپ) را به صندوق یکپارچهٔ پیام وصل کند.
همهٔ نشانی‌ها با پیشوند `{{BASE}}` شروع می‌شوند.

## کلید API

کلید را از صفحهٔ «کلیدهای API» همین فروشگاه بسازید (همان کلیدی که برای بقیهٔ APIهای نیم‌مارکتینگ هم هست).
دو دسترسی (scope) برای صندوق وجود دارد:

| دسترسی | اجازه می‌دهد |
|---|---|
| `inbox_read` | خواندن گفتگوها، پیام‌ها، مخاطبان و بخش‌ها |
| `inbox_write` | آوردن پیام مشتری به صندوق، پاسخ دادن، ثبت مخاطب، ساختن **پیش‌نویس** ارسال گروهی |

کلید را در هدر `X-Api-Key` بفرستید. کلید «تست» همهٔ بررسی‌ها را انجام می‌دهد ولی هیچ چیزی را تغییر نمی‌دهد
و پاسخ‌هایش `"sandbox": true` دارند. سقف تعداد درخواست طبق سقفِ عمومیِ APIهای نیم‌مارکتینگ است.

```bash
curl -H "X-Api-Key: up_live_..." "{{BASE}}conversations/?state=ESCALATED&limit=20"
```

## نشانی‌ها

### فهرست گفتگوها — `GET conversations/`
پارامترها: `state` (AI، HUMAN، ESCALATED، RESOLVED)، `channel` (TELEGRAM، BALE، EITAA، RUBIKA، WEBCHAT، SMS، WHATSAPP، API)، `limit` (تا ۲۰۰).

### پیام‌های یک گفتگو — `GET conversations/<id>/messages/`
یادداشت‌های داخلی تیم هرگز در این فهرست نیستند.

### پاسخ دادن — `POST conversations/<id>/reply/`
```json
{"text": "سفارش شما امروز ارسال شد."}
```
پاسخ: `{"delivered": true, "reason": ""}`. اگر کانال خاموش یا وصل‌نشده باشد `delivered` نادرست است و `reason` علت را می‌گوید.

### آوردن پیام مشتری از سیستم شما — `POST messages/`
```json
{"sender_id": "user-42", "name": "سارا", "phone": "09120000000", "text": "سفارشم کجاست؟", "message_id": "m-1001"}
```
`message_id` را بدهید تا ارسال دوباره‌ی همان پیام دو بار ثبت نشود. اگر شمارهٔ موبایل بدهید، این مشتری با همان آدم در کانال‌های دیگر (تلگرام، پیامک…) یکی می‌شود.
گفتگو با کانال `API` ساخته می‌شود؛ پاسخ‌های تیم را با وب‌هوک `message.sent` بگیرید.

### مخاطبان — `GET contacts/` و `POST contacts/upsert/`
```json
{"phone": "09120000000", "name": "علی", "tags": ["باشگاه"]}
```
با شمارهٔ موبایل ساخته یا به‌روز می‌شود (شماره‌های فارسی و `+98` هم قبول است).

### بخش‌ها — `GET segments/`
بخش‌های آماده (مثل «مشتریِ دائمی») و بخش‌های خودتان.

### پیش‌نویس ارسال گروهی — `POST broadcasts/`
```json
{"name": "تخفیف آخر هفته", "text": "سلام {name}!", "segment_id": 3, "channels": ["BALE"]}
```
فقط **پیش‌نویس** ساخته می‌شود. تأیید و ارسال همیشه کار یک آدم (مالک یا مدیر) در پنل است؛ هیچ API‌ای ارسال گروهی را تأیید نمی‌کند.

## وب‌هوک‌های خروجی

در بخش «توسعه‌دهندگان» نشانی (فقط `http`/`https` روی درگاه‌های ۸۰، ۴۴۳، ۸۰۸۰، ۸۴۴۳ و آدرس عمومی) و رویدادهای دلخواه را ثبت کنید.
هر رویداد یک `POST` با بدنهٔ JSON است:

```json
{"id": "evt_ab12cd34", "event": "message.received", "store_id": 5, "created_at": "2026-11-16T09:30:00+00:00",
 "data": {"conversation_id": 81, "message_id": 903, "channel": "BALE", "text": "سلام", "customer": {"id": 12, "name": "سارا"}}}
```

### رویدادها
- `message.received` — پیام تازه از مشتری
- `message.sent` — پاسخ ارسال شد (تیم یا ربات)
- `conversation.created` — گفتگوی تازه
- `conversation.assigned` — گفتگو به کسی سپرده شد
- `conversation.handoff` — ربات گفتگو را به آدم داد
- `conversation.closed` — گفتگو بسته شد
- `conversation.reopened` — گفتگوی بسته‌شده دوباره باز شد
- `sla.warning` — SLA در آستانهٔ رد شدن
- `sla.breached` — SLA رد شد
- `survey.answered` — مشتری نظرسنجی را پاسخ داد
- `contact.opted_out` — مخاطب از پیام‌های تبلیغاتی خارج شد
- `broadcast.approved` — ارسال گروهی تأیید شد
- `broadcast.finished` — ارسال گروهی تمام شد

گفتگوهای آزمایشی (علامت «آزمایشی») هیچ رویدادی نمی‌فرستند.

### تأیید امضا
هر درخواست هدر `X-Inbox-Signature: t=<زمان>,v1=<امضا>` دارد. امضا برابر است با HMAC-SHA256 از متنِ `"<زمان>." + بدنهٔ خام` با «رمز» همان نشانی (در صفحهٔ وب‌هوک). زمان‌های قدیمی‌تر از ۵ دقیقه را رد کنید تا کسی نتواند درخواست را بعداً دوباره بفرستد.

```python
import hmac, hashlib, time

def verify(secret: str, body: bytes, header: str, tolerance=300) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    if abs(time.time() - int(parts["t"])) > tolerance:
        return False
    expected = hmac.new(secret.encode(), parts["t"].encode() + b"." + body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, parts["v1"])
```

### تلاش دوباره
پاسخ‌های `2xx` موفق‌اند. غیر از آن، ارسال پس از ۱، ۵، ۳۰، ۱۲۰ و ۷۲۰ دقیقه دوباره امتحان می‌شود (حداکثر ۶ بار). اگر یک نشانی ۲۵ بار پشت‌سرهم خطا بدهد خاموش می‌شود و باید دوباره روشنش کنید.
هدرهای `X-Inbox-Event` و `X-Inbox-Delivery` نوع رویداد و شناسهٔ یکتای آن را می‌دهند؛ شناسه را نگه دارید تا ارسال تکراری را نادیده بگیرید.

## ویجت چت سایت

```html
<script src="https://<نشانی-سرویس>/api/v1/widget/<کلید-ویجت>.js" async></script>
```
کد آماده را در صفحهٔ «کانال‌ها ← چت سایت» می‌بینید. اگر «سایت‌های مجاز» را پر کنید، ویجت فقط روی همان سایت‌ها کار می‌کند.
