# صندوق یکپارچهٔ پیام (نیم‌چت‌مانند) — راهنمای فنی و عملیاتی

صندوقِ پیامِ NM حالا یک «پنجره برای همهٔ کانال‌ها» است: تلگرام، بله، ایتا، روبیکا، پیامک، چتِ سایت (و واتساپ رسمی، خاموش)،
با تیم و نقش، تقسیم خودکار، SLA، ربات پاسخ‌گو و واگذاری، ارسال گروهی با تأییدِ مالک، CRM و بخش‌ها، پیگیری و نظرسنجی، API و وب‌هوک.
برند، متن و طراحیِ nim.chat کپی نشده؛ فقط الگوی کارِ «صندوقِ مشترکِ چندکاناله» الهام‌بخش بوده است.

برنامهٔ جدید `backend/apps/inbox` است و جدول‌های `apps.customers` را **تغییر نمی‌دهد**: هر چه صندوق اضافه می‌کند (ردیفِ «متا»ی گفتگو، نویسندهٔ پیام،
مخاطب، اتصال کانال…) در جدول‌های خودش است و با کلیدِ خارجی به گفتگو/پیام/مشتری وصل می‌شود.

## کانال‌ها — چه چیزی واقعاً بررسی شد

| کانال | روش | وضعیتِ راستی‌آزمایی |
|---|---|---|
| بله | API شبیهِ تلگرام: `tapi.bale.ai/bot<token>/<method>` | شکلِ پاسخِ توکنِ غلط (HTTP 401) از سرویسِ زنده دیده شد؛ بقیه با سرورِ ساختگیِ HTTP آزموده شد |
| ایتا (ایتایار) | `eitaayar.ir/api/<token>/<method>`؛ پوششِ خطا داخلِ بدنه با HTTP 200 | شکلِ خطا از سرویسِ زنده دیده شد. **دریافتِ پیام به فعال‌بودنِ آن برای رباتِ مالک بسته است**؛ صفحه صریح می‌گوید «فقط ارسال» یا «ارسال و دریافت» |
| روبیکا | `botapi.rubika.ir/v3/<token>/<method>`؛ `getUpdates` یا `updateBotEndpoints` | توکنِ غلط (`INVALID_INPUT`) از سرویسِ زنده دیده شد؛ بقیه با سرورِ ساختگی |
| تلگرام | همان راهِ قبلی (توکن در پروفایلِ فروشگاه) + سلامت، پرسش دوره‌ای، ثبتِ وب‌هوک | با سرورِ ساختگی؛ سرورِ ایران ممکن است به تلگرام دسترسی نداشته باشد (سلامت می‌گوید) |
| چت سایت | یک `<script>`؛ نشستِ مرورگر، سقفِ نرخ، سایت‌های مجاز | آزموده شد؛ در سایت‌ساز با بخشِ «کدِ سفارشی» (عیناً در سایتِ منتشرشده می‌نشیند) |
| پیامک | صفِ گوشی‌های `apps.mobile` (ارسال) و جدولِ پیامک‌های دریافتی (دریافت) | آزموده شد؛ دریافت فقط وقتی مدیر سرویس «ذخیرهٔ پیامک‌های دریافتی» را در بخش موبایل روشن کند |
| اینستاگرام | همان راهِ قبلی (نوین‌هاب + تأییدِ اپ Meta) | تغییری نکرد؛ فقط راهنما و آدرسِ وب‌هوک در صفحهٔ کانال‌ها |
| واتساپ | Cloud API رسمی؛ **پیش‌فرض خاموش** و بدونِ حسابِ رسمی روشن نمی‌شود | قالبِ پیام/امضا/تأییدِ وب‌هوک با داده‌های ساختگی آزموده شد؛ حسابِ رسمی دست مالک نبود |

هیچ پیامِ واقعی از هیچ‌جا فرستاده نشد؛ هیچ توکنی در کد یا مخزن نیست.

## قاعده‌های ایمنی (هرکدام تست دارد)

- ربات هرگز حدسِ کم‌اطمینان را نمی‌فرستد: پاسخ نگه داشته می‌شود («پیش‌نویسِ ربات» برای تیم) و مشتری فقط جملهٔ واگذاری را می‌بیند.
- سیاستِ داده («فقط محلی») همان قبلی است؛ ربات از همان دروازه (`services.ai.gateway`) رد می‌شود و نبودنِ AI باعث «ربات جواب نداد» و تلاشِ دوباره می‌شود.
- یادداشتِ داخلی جدولِ جدایی است؛ هیچ پرامپتی از آن ساخته نمی‌شود و به مشتری نمی‌رسد.
- ارسال گروهی: پیش‌نمایش ← تأییدِ مالک/مدیر (سازنده خودش نمی‌تواند) ← سقفِ هر کانال در دقیقه ← «لغو» تا لحظهٔ ارسال رعایت می‌شود ← کانالِ خراب خودش می‌ایستد. API فقط پیش‌نویس می‌سازد.
- پیامکِ تبلیغاتی فقط با «تأییدِ کمپین» در دروازهٔ پیامک و ساعتِ سکوتِ همان دروازه.
- پیامکِ دریافتی: فقط پیامِ تازه، فقط از شمارهٔ موبایلِ واقعی، و به‌طور پیش‌فرض فقط از مخاطب‌های شناخته‌شده (پیامکِ بانک و شخصیِ گوشی وارد نمی‌شود).
- وب‌هوکِ خروجی: امضای HMAC با زمان، تلاش دوباره، خاموش‌شدنِ نشانیِ مرده، و ضدِ SSRF با همان `services.safenet` (آدرسِ بررسی‌شده همان است که صدا زده می‌شود؛ بدون ریدایرکت).
- گفتگوی آزمایشی (`is_test`): بدونِ SLA، رویداد، آمار، بخش و ارسالِ گروهی.

## نشانیِ عمومیِ سایت و https (مهم برای ویجت و وب‌هوک)

کدِ ویجتِ چت (`<script src=…>`) و نشانیِ وب‌هوکِ بله/ایتا/روبیکا/تلگرام روی «نشانیِ عمومیِ سایت» ساخته می‌شود، به این ترتیب:
۱) کادرِ «نشانی عمومی سایت» در صفحهٔ «کانال‌ها» (`InboxSettings.public_base_url`)، ۲) `PUBLIC_BASE_URL` سایت (اگر نشانیِ واقعی باشد، نه `localhost`)،
۳) نشانیِ همان صفحه‌ای که پنل با آن باز شده. اگر نتیجه `http://` باشد (مثل `http://87.107.160.17:8040`)، پنل کنارِ کد و وب‌هوک‌ها هشدار می‌دهد:
مرورگر اجازه نمی‌دهد صفحهٔ https (مثل سایتِ چغر) اسکریپتی را از http بارگذاری کند، و پلتفرم‌ها وب‌هوکِ http را نمی‌پذیرند. تا آن موقع ربات‌ها با «پرسش دوره‌ای» کار می‌کنند.
**کارِ مالک:** یک دامنه با گواهیِ https برای این سرور راه بیندازد و نشانیِ آن را در همان کادر بنویسد؛ کدِ ویجت خودکار با آن ساخته می‌شود.

نشانیِ وب‌هوک و کلیدِ ویجت فقط برای مالک/مدیر (کسی که اجازهٔ تنظیمات دارد) نمایش داده می‌شود؛ پشتیبان و بیننده فقط وضعیتِ کانال را می‌بینند.

تلگرام: سرورِ داخلِ ایران معمولاً به `api.telegram.org` دسترسی ندارد و **هر دو** راهِ دریافت (وب‌هوک و پرسش دوره‌ای) به این اتصال نیاز دارند؛
کارتِ تلگرام همین را (با یک بررسیِ واقعیِ ۳ ثانیه‌ای که چند دقیقه نگه داشته می‌شود) می‌نویسد و بله/ایتا/روبیکا را پیشنهاد می‌کند.

محدودیتِ نرخِ ویجت (چت‌های تازه در ساعت برای هر نشانی/فروشگاه) در Redis نگه داشته می‌شود، پس برای همهٔ workerها یکی است و با reload صفر نمی‌شود؛ بدونِ Redis به حافظهٔ همان فرآیند برمی‌گردد.

## «منتظر پاسخ» یک تعریف دارد

گفتگو «منتظر پاسخ» است وقتی (الف) دستِ آدم است (HUMAN / ESCALATED) و بعد از آخرین پیامِ مشتری هیچ‌کس از تیم ننوشته (یا ساعتِ SLA می‌دود)، یا (ب) ربات خواسته جواب بدهد و نتوانسته.
گفتگویی که تیم جوابش را داده «باز» است، نه «منتظر». همین تعریف (`owed.py`) پشتِ شمارندهٔ تب، کاشیِ صفحهٔ تیم، `stats/` و «بدون مسئول» است؛ «مال من» هم فقط گفتگوهای بازِ من را می‌شمارد و همان را باز می‌کند.
فهرستِ گفتگوها صفحه‌بندی دارد (`limit` و `offset`، «نمایش بیشتر»، سقفِ ۵۰۰ در هر درخواست) و هزینهٔ آن به تعدادِ ردیف‌ها بستگی ندارد.

## کلمه‌های «آدم می‌خواهم»

فقط کلمهٔ کامل (یا عبارتِ کامل) جور درمی‌آید، نه تکه‌ای از کلمه: «مدیر»، «آدم»، «مسئول»، «صحبت با» و «human» دیگر در فهرستِ پیش‌فرض نیستند چون در پرسش‌های عادیِ مشتریِ چغر
(«مدیریتِ ورزشکاران»، «آدم‌های دیابتی») می‌آیند. کلمهٔ خودتان را هم نگذارید اگر مشتری‌های شما آن را در پرسش‌های معمولی می‌نویسند (مثلاً «مربی»).

## نظرسنجی

یک پیام فقط وقتی پاسخِ نظرسنجی است که گفتگو هنوز بسته باشد و پیام «خودِ عدد» (۵، ۴ از ۵، ۵ ستاره) یا عدد + نظرِ کوتاهِ بدونِ پرسش باشد (۴ ممنون).
«۳ نفر هستیم و می‌خوام ثبت‌نام کنم، چطوری؟» پیامِ عادی است: گفتگو دوباره باز می‌شود و تیم خبردار می‌شود.

## ارسال گروهی: اگر یک کانال نرسید

با گزینهٔ «یک پیام برای هر نفر»، اگر ارسال روی کانالِ انتخاب‌شده شکست بخورد، همان نفر روی کانالِ بعدیِ خودش (در همان کانال‌هایی که مالک تأیید کرده، وصل و روشن، و لغو نکرده) در صف می‌رود؛
دلیلِ شکست روی ردیفِ اول می‌ماند و آمارِ ارسال «رفته به کانال بعدی» را جدا نشان می‌دهد.

## دستورها

```bash
cd backend
python manage.py migrate                      # صندوق: جدول‌های تازه، بدونِ دست‌زدن به جدول‌های قبلی
python manage.py seed_inbox_demo --store 34   # چغر: پیش‌نویسِ تنظیمات + گفتگوهای آزمایشیِ علامت‌دار (هیچ کانالی روشن نمی‌شود)
python manage.py test apps.inbox --noinput
```

## چه چیزی با روشن‌شدنِ سرورِ پردازش خودکار شروع می‌شود

ربات از همان `ollama.generate`ِ ایجنتِ فروش استفاده می‌کند؛ نصب یا مدلِ تازه‌ای لازم نیست. آزمونِ خودکارِ `inbox_bot`
(گروهِ «متن» در «آزمونِ خودکارِ سرورِ پردازش») بعد از روشن‌شدنِ گره یک پرسشِ واقعیِ مشتریِ چغر را با مدلِ خودِ مالک می‌فرستد و می‌سنجد
که فارسی و کوتاه جواب بدهد، عدد و قیمت از خودش درنیاورد و جایگزینِ مربی نشود.
