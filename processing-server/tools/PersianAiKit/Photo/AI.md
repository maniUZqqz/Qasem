# ویرایش با هوشِ مصنوعیِ بینا (کم‌هزینه)

**ایده:** هوشِ مصنوعی عکس نمی‌سازد و پیکسل دست نمی‌زند. فقط عکسِ کوچک را **می‌بیند** و یک «نسخهٔ ویرایش» (همان JSONِ صفحهٔ وب) **می‌نویسد**؛ ویرایشِ واقعی را موتورِ خودمان روی دستگاه، در اندازهٔ اصلی و بی کاهشِ کیفیت انجام می‌دهد. پس:

- **ارزان:** برای هر عکس چند هزار توکن، نه تولیدِ تصویر. با مدل‌های رایگان صفر.
- **امن:** خروجیِ مدل از صافیِ نسخه می‌گذرد: کلیدِ ناشناخته دور ریخته، عددِ بیرون از بازه بریده می‌شود؛ مدل نمی‌تواند عکس را «خراب» کند.
- **قابلِ ادامه:** نتیجه همان نسخه است ⇒ در صفحهٔ وب با لغزنده‌ها ریزش می‌کنید یا برمی‌گردانید (Ctrl+Z).
- **حریمِ خصوصی:** فقط یک JPEGِ ۵۱۲ پیکسلی (~۱۰ کیلوبایت) و چند خط عدد از دستگاه بیرون می‌رود؛ عکسِ اصلی نه. با مدلِ محلی (LM Studio، Ollama) هیچ‌چیز بیرون نمی‌رود.

## مراحل (`POST /api/docs/{id}/ai-edit`)

1. **اندازه‌گیریِ محلی (رایگان):** صدک‌های روشنایی، سوختگی، کنتراست، اشباع، ته‌رنگ (از رنگ‌های خنثی)، تیزی، نویز، یکدست بودنِ زمینه، هیستوگرام.
2. **نسخهٔ خودکار (رایگان):** همان دکمهٔ «✦ خودکار» — نقطهٔ شروعِ معقول.
3. **یک درخواست:** متنِ ثابت (فهرستِ ۵۸ ابزار با بازه و معادلِ فتوشاپ، ~۱۲۰۰ توکن) + هدفِ شما + اندازه‌گیری‌ها + نسخهٔ خودکار + **عکسِ ۵۱۲ پیکسلی** ⇒ مدل فقط JSON برمی‌گرداند.
4. **اجرا:** موتور نسخه را روی پیش‌نمایش اجرا می‌کند.
5. **یک نگاهِ دوباره (اختیاری، `MaxRounds: 2`):** مدل نتیجه را می‌بیند و یا `{"done": true}` می‌گوید یا نسخهٔ اصلاح‌شده را می‌دهد.
6. **اگر نشد:** کلید نیست، اعتبار تمام شده، مدل جواب نداد یا JSONِ خراب داد ⇒ همان نسخهٔ خودکار اعمال و دلیلش گفته می‌شود. مدل‌ها به ترتیب امتحان می‌شوند (اولی جواب نداد ⇒ دومی).

```
شما: «عکسِ کالا برای فروشگاه با زمینهٔ سفید»
  └─► اندازه‌گیری + خودکار (محلی) ─► مدل (عکسِ ۵۱۲px + عددها) ─► نسخهٔ JSON
        └─► موتور: پیش‌نمایش ─► مدل: «درست است» یا اصلاح ─► نسخهٔ نهایی ─► خروجی در اندازهٔ اصلی
```

## هزینه

| بخش | توکن (تقریبی) |
|---|---|
| متنِ ثابت (فهرستِ ابزارها و قاعده‌ها) | ~۱۲۰۰ (`Run-SelfTest.bat --prompt` دقیقش را نشان می‌دهد) |
| هدف + اندازه‌گیری‌ها + نسخهٔ خودکار | ~۲۰۰ تا ۳۰۰ |
| عکسِ ۵۱۲ پیکسلی | ~۲۵۰ تا ۸۰۰ (بسته به مدل) |
| پاسخِ مدل (فقط JSON) | ~۱۰۰ تا ۳۰۰ (سقف: `MaxTokens` = ۹۰۰) |
| دورِ دوم (گفت‌وگوی قبلی + عکسِ نتیجه) | تقریباً دو برابرِ دورِ اول |

یعنی حدودِ **۴ تا ۶ هزار توکنِ ورودی و چند صد توکنِ خروجی برای هر عکس با دو دور** (با یک دور نصف). با مدلی که مثلاً ۰٫۱ دلار برای هر میلیون توکنِ ورودی می‌گیرد، این کمتر از یک‌دهمِ سنت برای هر عکس است. مدل‌های بیناییِ **رایگانِ** OpenRouter (`auto-free`) هزینه ندارند (محدودیتِ تعداد در روز دارند). متنِ ثابت در همهٔ درخواست‌ها یکسان است ⇒ سرویس‌هایی که «کشِ پرامپت» دارند آن را ارزان‌تر حساب می‌کنند. مصرفِ واقعیِ هر ویرایش در پاسخ (`promptTokens`، `completionTokens`) و در صفحه نوشته می‌شود.

## تنظیم (`appsettings.json` ⇐ `Photo:Ai`)

```json
"Ai": {
  "BaseUrl": "https://openrouter.ai/api/v1",
  "ApiKey": "sk-or-...",
  "Models": "auto-free",
  "MaxRounds": 2,
  "ThumbSide": 512
}
```

- **هر سرویسِ سازگار با OpenAI** که عکس می‌پذیرد (`/chat/completions` با `image_url`): OpenRouter، سرویس‌های ایرانیِ سازگار با OpenAI، OpenAI، …
- `Models`: نامِ مدل‌ها با ویرگول، به ترتیبِ امتحان؛ `auto-free` ⇒ مدل‌های بیناییِ رایگانِ OpenRouter (هر ۶ ساعت از خودش خوانده می‌شود؛ Qwen، Gemma، Llama، Mistral، … در اولویت). می‌شود ترکیب کرد: `"qwen/qwen2.5-vl-72b-instruct,auto-free"`.
- **مدلِ محلی (بی اینترنت، بی کلید):** LM Studio یا Ollama با یک مدلِ بینا (مثلاً Qwen2.5-VL یا Gemma 3) ⇒ `"BaseUrl": "http://127.0.0.1:1234/v1"` (LM Studio) یا `"http://127.0.0.1:11434/v1"` (Ollama) و نامِ مدل در `Models`. نشانیِ محلی کلید نمی‌خواهد. مدلِ بینای کوچک هم چند گیگابایت حافظه می‌خواهد ⇒ مثلِ BiRefNet جایش سرور است.
- `MaxRounds: 1` ⇒ نصفِ هزینه، بی نگاهِ دوباره. `ThumbSide` کوچک‌تر ⇒ ارزان‌تر ولی مدل جزئیات را کمتر می‌بیند.

## استفاده

در صفحه: زبانهٔ **هوشِ مصنوعی** ⇐ هدف ⇐ «✦ ویرایش با هوشِ مصنوعی». از برنامه:

```bat
curl -X POST -H "Content-Type: application/json" -d "{\"goal\":\"عکسِ کالا برای فروشگاه با زمینهٔ سفید\"}" http://localhost:5670/api/docs/<id>/ai-edit
```

> در Git Bash متنِ فارسی داخلِ آرگومانِ curl خراب می‌شود؛ از cmd یا فایل (`-d @goal.json`) استفاده کنید.

پاسخ:

```json
{
  "recipe": { "adjust": { "exposure": 0.25, "whites": 18, "clarity": 12, "sharpen": 40 },
              "background": { "remove": true, "method": "auto", "color": "#ffffff", "cleanup": -1, "shadow": 20 },
              "output": { "square": true, "padding": 0.06, "longEdge": 2000, "format": "jpeg", "quality": 92 } },
  "notes": "نور کمی بیشتر، سفیدها تمیزتر و زمینهٔ سفید با قابِ مربع.",
  "usedAi": true,
  "promptTokens": 4210, "completionTokens": 260,
  "steps": [ { "round": 1, "model": "qwen/...", "done": false, "seconds": 6.1 },
             { "round": 2, "model": "qwen/...", "done": true,  "seconds": 4.3 } ]
}
```

نسخه ذخیره **نمی‌شود** (پیشنهاد است): صفحه خودش آن را در تاریخچه می‌گذارد؛ از برنامه با `PUT /api/docs/{id}/recipe` ذخیره و با `POST /api/docs/{id}/export` خروجی بگیرید.

## ابزارها برای عاملِ بیرونی (function calling)

اگر خودتان یک عاملِ هوشِ مصنوعی دارید (مثلاً دستیارِ فروشگاه)، همین ابزارها را به او بدهید: `GET /api/tools/openai` سه تابع در قالبِ `tools`ِ OpenAI برمی‌گرداند — با بازه و توضیحِ هر لغزنده، که مدل را از عددِ بی‌معنی دور نگه می‌دارد:

| تابع | پارامترها | به کدام مسیر |
|---|---|---|
| `analyze_photo` | `id` | `GET /api/docs/{id}/analyze` |
| `edit_photo` | `id` + نسخه (`preset`، `adjust`، `curve`، `crop`، `spots`، `background`، `output`) | `PUT /api/docs/{id}/recipe` بعد `POST /api/docs/{id}/render` (عکسِ پیش‌نمایش را به مدل نشان دهید) |
| `export_photo` | `id` | `POST /api/docs/{id}/export` |

```python
import requests, json
B = "http://localhost:5670"
tools = requests.get(f"{B}/api/tools/openai").json()     # به مدلِ خودتان بدهید

def run_tool(name, args):                                 # وقتی مدل ابزاری را صدا زد
    doc = args.pop("id")
    if name == "analyze_photo":
        return requests.get(f"{B}/api/docs/{doc}/analyze").json()["text"]
    if name == "edit_photo":
        requests.put(f"{B}/api/docs/{doc}/recipe", json=args)
        img = requests.post(f"{B}/api/docs/{doc}/render", params={"max": 512}).content
        return img                                        # به‌صورتِ عکس به مدل برگردانید تا نتیجه را ببیند
    if name == "export_photo":
        open(f"{doc}.jpg", "wb").write(requests.post(f"{B}/api/docs/{doc}/export").content)
        return "saved"
```

`analyze_photo` متنِ کوتاهِ انگلیسی برمی‌گرداند (مثل «luminance median 0.41, clipped highlights 2.1%, plain background: yes…») — ارزان‌تر از فرستادنِ عکسِ بزرگ، و مدل‌ها نوردهی و ته‌رنگ را از عدد دقیق‌تر از چشم تشخیص می‌دهند.

## چرا این روش (و نه تولیدِ تصویر)

| | این روش (نسخهٔ ویرایش) | مدلِ تولید/ویرایشِ تصویر |
|---|---|---|
| هزینه برای هر عکس | چند هزار توکن (یا صفر) | چند ده برابر |
| کیفیت و اندازه | اندازهٔ اصلی، بی‌افت | معمولاً کوچک‌تر، جزئیاتِ ساختگی |
| وفاداری به کالا | پیکسل‌ها همان کالاست (برای فروشگاه مهم) | ممکن است شکل یا نوشتهٔ کالا عوض شود |
| قابلِ ویرایش و برگشت | ✓ (همان لغزنده‌ها) | ✗ |
| بی اینترنت | «خودکار» همیشه؛ با مدلِ محلی همه | معمولاً ✗ |
